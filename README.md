## 🥇 Gold: curated and ready to consume

Five projects, each one an attempt to get a piece of engineering all the way to something usable, not just something that runs.

<br>

**Walmart Retail Intelligence Pipeline**
*A retail data pipeline that doesn't stop at the tables it builds*

Six raw retail entities, moved through a bronze → silver → gold lakehouse on Databricks, orchestrated end to end by a single Airflow DAG, transformed entirely in dbt. The gold layer isn't the finish line. It feeds a Streamlit dashboard that answers the four questions a retail stakeholder actually asks: revenue, store performance, product trends, order status. Live from Databricks when connected, a local snapshot when it's not, so the demo never depends on someone else's credentials being configured correctly.

`Python` `Airflow` `Databricks` `dbt` `Streamlit`

<br>

**Airbnb Analytics Pipeline**
*A medallion pipeline built the way a warehouse team would actually build it*

An end to end Airbnb style analytics project on Snowflake and AWS S3, with dbt owning every transformation. CSV source data lands in S3, stages into Snowflake, and moves through a full bronze/silver/gold medallion: incremental models, SCD Type 2 snapshots for bookings, hosts, and listings, custom macros, and a one big table gold model backed by dbt tests. Live on GitHub.

`Snowflake` `AWS S3` `dbt`

<br>

**RideStream**
*A query layer for people who don't know the schema*

A STAR schema is efficient to query and useless to someone who doesn't know it exists. I built an Event Hub to Data Factory to Databricks medallion pipeline, modeled it into SCD Type 1 and Type 2 dimensions, and put a Claude backed natural language to SQL layer on top of it, validated and logged rather than trusted blindly. I tested it with 20 questions spanning joins, aggregations, and deliberately out of scope requests: 100% success on the answerable ones, 100% correct rejection on the rest, including a `DELETE` it should never have generated in the first place.

`Azure Event Hub` `Data Factory` `Databricks` `PySpark` `Delta Lake` `Claude API`

<br>

**StudyOS**
*A study assistant that actually knows my notes*

Generic chatbots don't know what I've already learned. StudyOS grounds its answers in my own knowledge base instead of producing plausible sounding fiction. The hard part was never the chat interface, it was retrieval: chunking, embeddings, and grounding evaluations that catch the assistant the moment it starts making things up.

`LangChain` `Claude API` `ChromaDB` `SentenceTransformers`

<br>

**Buena**
*Property PDFs that stop needing a human typist*

Before: one property document meant fourteen rows of manual data entry. After: the model reads the PDF once, extracts structured records, and a human reviews one submission instead of retyping fourteen. AI extraction on messy real world documents fails in strange, specific ways, so I spent about as much time on the 87 test safety net as I did on the extraction pipeline itself.

`Next.js` `NestJS` `PostgreSQL` `Prisma` `Claude API`
